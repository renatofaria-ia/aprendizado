Como o GitHub renderiza Mermaid

Resposta curta

O GitHub reconhece o bloco Mermaid, interpreta sua definição e mostra o resultado como um diagrama na página.

O caminho

Uma analogia

Pense em um briefing de produto: você entrega uma especificação textual, o time de design a interpreta e o cliente recebe uma tela pronta. No GitHub, o bloco Mermaid é o briefing, a biblioteca é o intérprete e o diagrama é a tela.

Onde isso se encaixa

O GitHub tem essa integração dentro do seu renderizador de Markdown. Por isso, o mesmo tipo de bloco pode aparecer em README, Issues, Pull Requests, Discussions, Wikis e arquivos Markdown compatíveis.

O repositório guarda texto fácil de versionar, enquanto o leitor vê o fluxo. Fora do GitHub, um HTML precisa carregar Mermaid ou receber um SVG gerado durante a build.

Passos essenciais

  1. 1. Escreva o fluxo em texto.Pronto quando a definição começa com uma instrução Mermaid válida.
  2. 2. Marque a cerca como Mermaid.Pronto quando o bloco usa o identificador mermaid.
  3. 3. Publique em uma área Markdown suportada.Pronto quando a visualização mostra o desenho, não apenas o texto.

Verifique se entendeu

O que diferencia Mermaid de um bloco de código comum?

O identificador de linguagem mermaid e o suporte específico do renderizador de Markdown.

É preciso guardar uma imagem do diagrama?

Não. A definição textual pode ser versionada e o GitHub gera a apresentação visual ao renderizar a página.
